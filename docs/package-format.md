# 开发者适配：包格式 v1

本规范对应模组管理器 1.2.6，适用于其当前 V1 导入器。管理器统一提供 MelonLoader 0.7.3 和 .NET 6 运行环境；功能作者继续按该环境编写模组，无需引用管理器 DLL。

## 包结构

`.maydaymod` 是改了扩展名的标准 ZIP。打开压缩包就应看到 `manifest.json`，不要再套外层目录。

```text
manifest.json
Mods/
  Example.FlightMod.dll
Plugins/
  Example.StartupPlugin.dll
UserLibs/
  Example.Common.dll
```

`Mods` 放 MelonMod，`Plugins` 放需要早期加载的 MelonPlugin，`UserLibs` 放包自己的依赖。只创建需要的目录；`Mods` 与 `Plugins` 至少有一个 DLL。不能把任意来源 ZIP 当成有效模组包。

## 清单

```json
{
  "schemaVersion": 1,
  "id": "example-flight",
  "name": "飞行扩展示例",
  "version": "1.0.0"
}
```

- `id` 以小写字母开头，长度 3～48，只使用小写字母、数字和连字符。更新同一个模组时保持 ID 不变，先确认不与已有包重复。
- `name` 为显示名称，`version` 是发布版本；DLL 的版本声明与发布说明应同步更新。
- 安装后存放在 `Mods/MaydayPkg.<id>/`。不要依赖自己总是在游戏根目录的 `Mods` 下。

## 依赖与资源

V1 接受这三个目录下的托管 DLL，文件名应与程序集名一致。音频等资源请嵌入 DLL；当前格式不提供任意文件落地机制。模组自身的第三方依赖需随包提供，管理器不会在线查找、下载依赖，也不提供不同版本依赖的自动隔离。

不要在功能包中重复携带 `version.dll`、`MelonLoader`、`dotnet`、游戏本体、游戏生成程序集或其他加载器。不要把旧 `Mayday.ModMenu.dll` 菜单外壳打包进来。公共依赖发生同名冲突时，导入器会拒绝，需作者协调程序集名称／版本。

每包最多 128 条 ZIP 条目，压缩后与解压后总大小均限制 256 MiB。

## 生命周期与数据位置

导入默认关闭，启用、关闭、删除均在重启后生效，没有运行中卸载。遵循加载器的正常初始化和退出流程，不要把安装时点击「启用」当成运行时初始化事件。

持久存档和配置请写入独立数据目录，避免放在包目录内。管理器删除一个包会删除它自己的目录，不会替作者迁移数据。管理器也不会为所有模组提供自动备份或数据格式迁移。

## 界面共存

需要游戏菜单入口时，使用游戏原生 UI 和按钮事件，避开原有按钮列及其他模组入口。自己的弹层负责拦截背后点击，关闭时恢复原界面，不直接改写管理器的面板。不要为了提供一个设置页再附带综合菜单外壳。

规范没有要求模组添加热键；请按实际需求设计，清楚说明自己的操作入口。管理器和本仓库存档模组通过菜单按钮操作。

## 发布

提供清晰的安装方法、适用游戏版本、依赖、已知限制、升级／卸载方法和作者信息。将模组包作为独立 Release 附件发布；更新时保持 ID，当前管理器要求玩家先删除旧包并重启，再导入新包。

参见 [示例目录](../examples/example-flight/README.md)、[模组收录](../CONTRIBUTING.md) 与 [发布约定](releasing.md)。
